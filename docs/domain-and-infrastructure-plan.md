# 3サービス ドメイン・サーバー構成

作成日: 2026-08-26

## 3日公開で採用する構成

新しい独立ドメインを急いで3個購入せず、まず既存の `yunamatch.com` と同じ認証・データ基盤で限定公開する。

- バロマッチ: `https://yunamatch.com/valomatch`
- スタメイト: `https://yunamatch.com/stamate`
- 荘園メイト: `https://yunamatch.com/shoenmate`（権利者回答前はプレビューのみ）
- 共通規約・安全センター: `https://yunamatch.com/legal`
- 共通運営画面: `https://yunamatch.com/admin`

従来の `/valorant-preview`、`/brawl-preview`、`/identity-preview` も審査URL・既存リンク互換のため残す。新規告知では正式URLだけを使用する。

理由:

- OAuthのコールバックURL、Cookie、アカウント連携を1つの本番ドメインで検証できる
- 1つのD1でサービスIDごとにデータを分離し、管理・通報を一元化できる
- ドメイン購入後に名称や権利条件が変わっても、無駄な購入を避けられる
- 3日以内に安全確認へ時間を使える

## 次段階の推奨URL

独立ドメインではなく、まず以下のサブドメインを候補にする。

- `v.yunamatch.com`
- `stamate.yunamatch.com`
- `shoenmate.yunamatch.com`

Cloudflare WorkersのCustom Domainsは、同一Workerに複数ホスト名を設定でき、DNSと証明書も自動管理できる。ただし、追加前に以下を完了する。

1. OAuth各社へサブドメイン別コールバックURLを登録
2. Cookieの対象ドメイン、SameSite、Secure属性を確認
3. ログイン前のホスト名を認証後も維持する安全な戻り先を実装
4. 許可ホストの固定リストをサーバー側で検証し、任意URLへのリダイレクトを禁止
5. 各ゲーム権利者の名称・商標条件を確認

## データ構成

- D1: 1データベースを継続し、`service_id` で完全分離
- R2: アップロード画像を保存。ゲーム公式素材は保存しない
- 認証: 共通OAuth基盤。アカウント識別子をサービス別プロフィールへ紐付ける
- 管理: 共通 `/admin` でサービス別人数・募集・成立・チャット・未対応通報を確認
- 監査: 停止、復旧、画像削除、通報解決、管理者削除を記録

## 容量と料金判断

D1無料枠では日次上限に達するとAPIがエラーになり、検索・募集・チャットが失敗する。3サービスの限定公開前にWorkers Paidへ移行し、請求上限アラートを設定する。

監視する指標:

- Workers Requests / Errors / CPU time
- D1 rows read / rows written / storage / overloaded errors
- R2 storage / Class A・B operations
- OAuthエラー率
- チャット送信エラー、募集取得エラー、未対応通報
- サービス別の1日・1時間アクティブ人数

## ドメイン購入の判断

Cloudflare Registrarはレジストリ原価で購入・更新できるが、登録後の返金はない。以下を満たしたサービスだけ独立ドメインを購入する。

- 権利者の名称利用条件が確認済み
- 公式Xの名称が確定
- 7日間の限定テストで継続率とマッチ成立が確認できた
- OAuthプロバイダーに本番コールバックを追加できる
- 将来名称を変える可能性が低い

購入操作は料金が発生するため、候補名・初年度・更新価格を画面で確認したうえで運営者本人が最終確定する。
