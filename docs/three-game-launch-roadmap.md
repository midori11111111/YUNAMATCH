# 3サービス展開ロードマップ

対象サービス：バロマッチ（VALORANT）、荘園メイト（第五人格）、スタメイト（ブロスタ）

## 基本方針

- 3サイトを別々に作り直さず、認証・チャット・通報・管理・分析は共通基盤にする。
- ゲーム名、ランク、役割、募集条件、規約、ブランド表示だけをゲーム別に切り替える。
- 各社から明示的な許可がない限り、公式ロゴ・キャラクター画像・ゲーム内画像を使わない。
- 当面は全機能無料。広告・有料プラン・大会賞金は、各社規約と国内法務の再確認後に追加する。
- 「公式」「公認」と誤認される表現を使わず、全ページに非公式サービスである旨を表示する。

## 公開する順番

1. **スタメイト**：SupercellのFan Content Policyに沿った非公式・無料ベータとして開始。
2. **バロマッチ**：Riot Developer Portalの製品審査・登録状態を確認してからベータ開始。
3. **荘園メイト**：NetEaseへ送った問い合わせの回答を反映して開始。回答前は一般公開せずプレビューまで。

## 公開前の共通ゲート

以下が一つでも未完了なら大規模告知をしない。

- 運営者情報、問い合わせ先、利用規約、プライバシーポリシー、コミュニティガイドライン
- 電気通信事業の届出内容が3サービスを含むかの確認
- 恋愛・交際目的ではなくゲーム仲間探しであることの明記
- 年齢方針、未成年保護、性的勧誘・外部連絡先要求の禁止
- 通報、ブロック、ミュート、アカウント停止、異議申立て
- 管理者が通常DMを閲覧できず、通報対象だけ必要最小限確認する仕様と明記
- データ取得項目、利用目的、保存期間、削除方法、外部委託先の開示
- 管理画面の強い認証、操作ログ、権限分離、レート制限、バックアップ
- 障害・漏えい・荒らし発生時の対応手順
- 非公式表記と権利者へのリンク

## ゲーム別対応

### スタメイト

- Supercell名やBrawl Stars名をドメイン・サービス名の中心に使わない。
- Supercellの公式素材を加工してUI素材にしない。
- Fan Content Policy指定の非公式免責表示を掲載する。
- プレイヤータグ連携はBrawl Stars APIの利用条件を確認して実装する。
- 課金は保留。広告・寄付も公開後に改めて適合性を判断する。

### バロマッチ

- プレイヤー向け製品はAPIを使わない場合もRiotへの登録が必要という前提で進める。
- Riot Developer Portalで製品説明、URL、プライバシーポリシーを最新状態に保つ。
- 独自MMRや公式ランクの代替となる順位付けは作らない。
- Riot公式素材は、許された範囲が確定するまで使用しない。
- 審査回答前は機能デモに限定し、大規模集客を行わない。

### 荘園メイト

- NetEaseからの書面回答を保存し、許可された名称・素材・機能だけを採用する。
- 回答がない間は公式素材、キャラクター画像、公式ロゴを使わない。
- 第五人格の名称をドメインやサービス名に直接含めない。
- 問い合わせから7営業日後に一度だけ丁寧に追送する。

## サイト構成

- `yunamatch.com`：ブランドポータル。3サービスへの入口と運営情報。
- 各サービス：ゲームごとに独立ドメインまたはサブドメインを使用。
- 共通API：ログイン、プロフィール、募集、チャット、通知、通報、安全対策。
- 共通管理画面：サービス切替、ユーザー検索、通報確認、停止・復旧、障害状況、KPI。

管理画面で最低限見る項目：

- DAU / WAU / 新規登録 / 継続率
- いいね送信数、相互いいね率、申請承認率、初回メッセージ率
- 募集作成数、参加率、プレイ成立率
- 通報件数、種類、対応時間、停止件数
- APIエラー率、応答時間、サーバー使用量
- ゲーム別・流入元別の数値

## X・Discord運営

各サービスごとに公式XとDiscordを作る。ただし、問い合わせ窓口と運営ポリシーは共通化する。

公式Xの初期投稿：

1. サービスの目的と非公式表記
2. 30秒で分かる使い方動画
3. 安全対策と個人情報の扱い
4. 募集・マッチ成立例
5. フィードバック募集

Discordの初期チャンネル：

- はじめに / ルール / お知らせ / 使い方
- 募集 / 不具合報告 / 要望
- ゲーム別VC
- 運営専用の通報対応・障害対応チャンネル

## 発信者への営業

フォロワー数だけではなく、直近30日の投稿頻度、平均反応、参加型配信の有無、視聴者との距離で選ぶ。

優先順位：

1. フォロワー3,000〜30,000人で、参加型配信や募集投稿をしている人
2. 公式大会のキャスター、攻略投稿者、コミュニティ大会主催者
3. 30,000人以上の大型配信者

各ゲーム30人を候補化し、Aランク10人、Bランク10人、Cランク10人に分ける。最初の一斉送信はせず、Aランクへ1日3件まで個別文面で送る。

送信文面の型：

> 突然のご連絡失礼します。ゲーム仲間を条件から探せる非公式サービス「○○」を個人で開発しています。○○さんの参加型配信・募集投稿と相性が良いと感じ、ご連絡しました。まず実際に触っていただき、率直な改善点を1つ教えていただけないでしょうか。紹介は使用後に良いと思った場合だけで大丈夫です。URL：○○

最初から「宣伝してください」と頼まず、先に試用と改善意見を頼む。返信後に専用紹介URL、紹介文、短い動画、画像を渡す。金銭・無償提供が発生する場合は広告であることを明示する。

## 3日間ローンチスプリント

3日で「運営側が制御できる完成状態」まで持っていく。RiotやNetEaseなど第三者の審査回答だけは強制できないため、未回答サービスは限定プレビューで止め、回答後に設定一つで一般公開できる状態を完成とする。

### Day 1：法務・安全・設計を固定

午前：

- 3サービスの取得データ、保存先、保存期間、第三者提供を棚卸し
- 電気通信事業届出の対象サービス名・URL・機能追加の扱いを確認
- 恋愛目的ではないこと、年齢方針、未成年保護方針を確定
- 共通利用規約、共通プライバシーポリシー、コミュニティガイドラインを作成
- バロマッチ、荘園メイト、スタメイトのゲーム別特則を作成

午後：

- 公式素材を使わない独自ブランドへ統一
- 非公式表記、権利者ポリシーへのリンク、問い合わせ、削除請求導線を全画面へ設置
- 通報、ブロック、ミュート、停止、削除、異議申立ての仕様を固定
- 3サイトのドメイン候補とサーバー構成を確定
- 公式X・DiscordのIDを確保

Day 1終了条件：法務ページ一式が3サイトに表示され、危険機能の公開可否が一覧で判断できる。

### Day 2：3サイトと管理画面を完成

午前：

- ユナマッチの共通基盤から3サイト用テーマとゲーム項目を切り出す
- バロマッチ、荘園メイト、スタメイトのログイン・登録・探す・募集・チャット・プロフィールを接続
- 各ゲームのランク、役割、モード、募集条件を実データへ置換

午後：

- 共通管理画面にゲーム切替を追加
- ユーザー検索、停止・解除・削除、通報内容確認、監査ログを追加
- DAU、登録、マッチ、募集、通報、エラー、サーバー使用量をゲーム別に表示
- スマホ実機で登録からチャット・通報・退会まで通し確認
- 自動バックアップ、障害時のメンテナンス表示、レート制限を確認

Day 2終了条件：3サイトの主要導線が動き、運営者が安全に監視・停止・復旧できる。

### Day 3：公開判定・集客開始

午前：

- 3サービスを別アカウント2台で総合テスト
- 権限漏れ、DM消失、二重送信、通知、ブロック、退会、スマホ表示を重点確認
- 重大バグを修正し、各社審査状況で公開レベルを決定
- スタメイトは限定ベータ、バロマッチと荘園メイトは許可状況に応じて一般公開またはプレビュー公開

午後：

- 各公式Xへ固定投稿5本、30秒紹介動画、紹介画像、FAQを配置
- 各Discordへルール、使い方、募集、障害情報、問い合わせを配置
- 各ゲーム30人、合計90人の発信者候補リストを完成
- Aランク候補へ各ゲーム3人ずつ、合計9件の個別連絡を送信
- 紹介URLごとに流入・登録・マッチ成立を計測

Day 3終了条件：3サイトが公開可能な技術状態になり、公開可能なものは限定公開済み、外部回答待ちは公開ゲートで停止、公式SNSと最初の営業が開始済み。

## 3日間で後回しにするもの

- 有料会員、広告、寄付、賞金大会
- ネイティブアプリ化
- 高度なAIおすすめ
- 公式画像やAPIを使う追加機能
- 大規模インフルエンサーへの有償案件

この5点を混ぜると、3日で安全に公開できなくなるため第2段階へ回す。

## 判断基準

- 返信率10%未満：相手選定か最初の文面を変更。
- 登録完了率50%未満：入力項目とログイン導線を削る。
- 相互反応率10%未満：おすすめ順、オンライン優先、初回定型文を改善。
- 7日継続率15%未満：マッチ後の日程共有、再募集、通知を改善。
- 通報率が急増：集客を止め、安全対策を優先する。
